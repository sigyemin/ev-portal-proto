명세서 발행일자 : -

개발 안내 영수증 건별 인쇄 · 명세서 기간 조회 구현 — 실제 화면에는 노출하지 않습니다

1. 목적

  • 선택한 영수증을 건별로 한 장씩 인쇄합니다(스크롤되는 화면을 그대로 찍는 방식이 아님).

2. 구현 방식(적용 CSS)

  • 영수증 블록마다 break-after: page (구형 대비 page-break-after: always 병기).
  • break-inside: avoid — 블록이 페이지 중간에서 잘리지 않게.
  • 마지막 블록은 break-after: auto — 뒤에 빈 페이지가 생기지 않게.
  • @media print 에서 헤더·푸터·툴바·본문 목록·명세서 모달을 display:none.
  • 모달의 overflow/max-height 를 해제 — 인쇄본이 잘리지 않게.

3. ★주의 — 인쇄 경로가 두 갈래

  • 화면 인쇄(Ctrl+P) → 이 @media print 규칙이 적용됩니다.
  • 팝업 인쇄(printArea() 함수, 별도 창) → 이 규칙이 닿지 않습니다. 건별 분리는 영수증 블록(receiptBlock)의 인라인 스타일이 담당합니다. 모달의 [인쇄] 버튼은 이 팝업 경로를 탑니다.
  • 운영 구현 시 두 경로 중 어느 쪽을 쓸지 확정 필요.

4. 확인 방법

  • 영수증을 여러 건 선택해 모달을 연 뒤 Ctrl+P 미리보기에서 선택 건수 = 페이지 수 확인.

5. 미정(개발 협의 필요)

  • 다건 발급의 실제 방식(PDF 병합 / 개별 다운로드 / 인쇄 전용)은 개발 협의로 확정.

6. 명세서 — 월 단위 → 기간 조회 (ISS-132)

  • 명세서를 월 단위 고정에서 기간 조회로 전환. 모달 안 기간 선택은 목록 필터와 동일한 달력(datepicker/datepicker-input)을 쓴다. 최대 3개월 제한(MAX_DAYS=93)·시작일>종료일 방지를 명세서에도 동일 적용.
  • 단방향 동기화(목록 → 명세서): 명세서 확인 시 목록 필터바의 기간을 그대로 채워 연다. 모달을 닫았다 열면 목록 기간으로 재초기화.
  • 역방향은 하지 않는다(사용자 확정). 명세서에서 기간을 바꿔도 목록의 기간·조회 결과·체크박스 선택·더보기 위치는 보존한다. 이유: ① ISS-118 모달 닫힘 버그 재발 방지 — 명세서 변경이 목록을 재요청하면(연도 넘어갈 때) 페이지가 다시 그려져 모달이 사라졌다. ② 목록 작업 맥락(필터·선택·더보기) 보존. ③ 명세서는 조회 결과에서 파생된 증빙이라 인과가 역행하면 안 됨. → 명세서 전용 상태값(stmtStart/stmtFinish)을 목록 상태와 분리하고, 명세서 재조회는 fnGetList를 호출하지 않는다.

7. 명세서 미정(개발 협의 필요)

  • 운영 서버 쿼리 postStmtSQL 이 현재 yyyymm 단일 파라미터(AND A.TSDT >= #{yyyymm}||'01000000') 기준 → 기간 조건으로 전환 필요. 목록 조회가 이미 s_date_str/s_date_end 를 쓰므로 같은 방식으로 전환 가능. 미정(개발 협의).
